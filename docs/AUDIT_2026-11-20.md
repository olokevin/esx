Scope: every evolution-strategies implementation across ~/Project/ZO/Agentic-ESOpt, AgentES, AgentES-System,
ForkES, TreeES, HarnessES, specialists_team, ES-SEAgent. No file was modified.

Notation used below
- **tid** = per-tensor id. `B8(name)` = `int.from_bytes(blake2b(name, digest_size=8), "little")`.
- **mix64** = `(seed ^ tid) & 0xFFFF_FFFF_FFFF_FFFF`; **mixF** = `((seed*1000003 + salt) ^ tid) & 0x7FFF_FFFF_FFFF_FFFF` (Flipout).
- "dev gen" = `torch.Generator(device=param.device)`; "cpu gen" = `torch.Generator("cpu")`.
- "Agentic form" update = `theta += (alpha/N) * sum_i w_i eps_i`, `w` = z-scored reward, no 1/sigma.

## 1. Agentic-ESOpt `algorithms/es/` (intended shared layer)

### 1.1 `seeded_model_es.py` — `SeedReplayModelES` (tracked)
- Perturbs: scope `full` (all float params), `all_linear` (2-D weights minus embed_tokens/lm_head/norm, optional `target_modules` suffix filter), `lora` (params with `lora_` in name), or delegates to `StructuredES` for `fura|fura_s|iso|isobtt`.
- Noise: tid = `B8(param name)` (HF/vLLM `named_parameters` name incl. `.weight`), mix64, dev gen, `randn` fp32 in **chunks of 8,388,608** from one generator, cast to param dtype and added in place.
- sigma: absolute std per weight entry.
- Update: `/es/update(seeds, rewards, alpha, reward_normalization ∈ {none, zscore(ddof,eps), centered_rank})` → Agentic form `alpha/N`; fp32 accumulate per chunk, add once in param dtype. Revert = subtract noise (bf16 not exactly invertible); reset = replay history backwards.
- Serving: in-process object behind HTTP `/es/init|apply|revert|update|reset|status` (servers in task dirs, e.g. AHD `llama31_instruct_server.py`), client `model_es_client.ModelESClient`. One member at a time.

### 1.2 `structured_es.py` — `StructuredES` (tracked; also vendored in specialists_team)
- Scopes on the same tensors as all_linear: block-SVD per input block (`closest_factor_pair(in_f)`, optional `swap_blocks`):
  - `fura`: `W_j = A_j (R0_j + C_j)`, noise on core C; sigma absolute on core.
  - `fura_s`: `W_j = U_j diag(S0_j + c_j) Vh_j`, coef shape `(n_blk, k=min(out,b))`; **sigma absolute on singular values**.
  - `isobtt`: `R_j <- Cay(sigma Omega_j) R_j`; **sigma relative** `||dW||/||W||` (skew entries N(0,1/b)).
  - `iso`: `W <- C_L W C_R^T`, block-diag Cayley in per-seed permuted basis, never mixes fused `output_sizes` segments; sigma relative, `sigma/sqrt(2)` per side. fp32 master of W.
- Noise: dev gen, mix64 with the caller's tid (same as dense scope). fura/fura_s: one `randn(coef.shape)`; iso: randperm(s) then skew draws from one stream.
- Update: additive scopes Agentic form; rotation scopes = ordered product of per-seed Cayley factors at `(alpha/N) w_i` + recondition (Fro rescale for iso, Newton–Schulz for isobtt). Render writes dense weight (fura/fura_s/isobtt overwrite base with rounded block-SVD reconstruction at init, ~1.6e-3 rel in bf16).
- Serving: used by `SeedReplayModelES` and `vllm_math_es_worker.WorkerExtension` (same file, so they cannot drift). Also imported (helpers `_skew/_cayley/_rotate_*`, `_output_segments`, `closest_factor_pair`) by dense_inplace, rot_slots, fura_native, fura_s_pretransform, MobileWorld `mwt/fura.py`, `param_es_worker.py`, specialists `IsoSeq`.

### 1.3 `batched_es.py` — `BatchedStructuredES` (tracked; vendored in specialists_team)
- Batched `fura_s` / `isobtt`: replaces each linear's `quant_method` (or `nn.Linear.forward`) by factored forward `y = frame @ perturb(core, x)`; the dense weight is freed.
- Per-sequence members (Flipout-style activation trick). Slot 0 = unperturbed; table `(n_blk, N+1, k)`.
  - fura_s: member n gets `sigma * eps(seed_n)` = **same draw as unbatched fura_s** (dev gen, mix64).
  - isobtt: one shared skew `Omega` per generation from `group_seed(seeds)` (blake2b of packed seeds); member = sign flip `D_n Omega D_n` (`randint` signs) → **different trajectory from unbatched isobtt**.
- Update: Agentic form; cores stored in **model dtype (bf16)** with seeded stochastic rounding (`group_seed ^ 0x5DEECE66D`). Replay is not bit-compatible with unbatched fura_s (fp32 coef).
- Serving: in-process vLLM worker via `vllm_math_es_worker.set_population_math_es`; routing key `SamplingParams.extra_args["es_member"]` (0-based member, -1 = base).

### 1.12 `rot_slots.py`, `rot_tp.py`, `rot_hf.py` (untracked)
- `RotSlots`: per-token slot-routed spectrum-preserving rotations: `stages` layers of disjoint 2x2 Givens pairs (Triton kernel), modes `in|out|both|add`. Pairings from cpu gen seeded `tid & MASK63`, tid `B8(module + ".weight")`; angles from dev gen `seed ^ tid ^ (0x9E3779B97F4A7C15 * (stage+1+7*[out]))`, std `sigma/sqrt(stages*n_sides)` → nominal `||dW||/||W|| ~ sigma` (relative). `add` mode: `y += sigma*rms(y)*eps` (activation-scaled steering per linear). Optional trainable centre (`route_all`).
- `rot_tp`: `RotWorkerExt` for TP>1 via `collective_rpc` (`rot_install/rot_set_slots/rot_es_init/rot_es_update/rot_save_center`). **Update = Adam** on centre angles with `grad = -sum adv_i * noise_i / (N * sig_s^2)` (noise already × sigma → classic `1/sigma` ES gradient, not Agentic form). Pairs restricted to shards → member differs from tp=1.
- `rot_hf`: differentiable HF twin (BP on angles), maps vLLM fused layout to HF members.

### 1.13 `steer_slots.py` (untracked) — `SteerSlots`, `MultiSlots`, `HFSteer`

## 3. AgentES-System (design to adopt)

Files: `methods/flipout_dense.py` (`DenseFlipout`), `methods/engine.py` (`make_engine`), tests `test_flipout_parity.py`, `test_extras_parity.py`, benches `throughput, layer_micro, rollout, memory, grad_quality, multi_gpu`. Design docs: `~/Project/docs/AgentES-System/{design.md, plan.md, settings.md}`.

### 3.1 How perturbations are served
- One in-process vLLM engine (`SlotEngine`), **one engine batch holds the whole population**. Each request carries its member slot in `SamplingParams.extra_args["slot"]`; SlotEngine's patched `_model_forward` builds the per-token slot vector and calls `DenseFlipout.set_token_slots`, which writes it into a fixed `slot_buf` (in place). Slot 0 = centre (all-zero sign rows). Up to `n_slots` members.
- `DenseFlipout` is installed inside `GPUModelRunner.load_model` (monkeypatched for the duration of engine construction) — i.e. **before memory profiling and CUDA-graph capture** — and its buffer bytes are added to `runner.model_memory_usage` so vLLM sizes the KV cache correctly. `VLLM_DISABLE_COMPILE_CACHE=1` because the compile cache key does not see the patch.
- Linear layers: their `quant_method` (`UnquantizedLinearMethod`, bf16 only) is wrapped by `_FlipoutMethod.apply` = base kernel + Flipout term. All member state lives in **module buffers written in place** (`flip_E` or `flip_A/flip_B`, `flip_S/flip_R` or `flip_C`, `flip_slots`), and the extra GEMM always runs → graph-safe (no data-dependent branch).

### 3.2 Flipout math and variants (`variant`, `rank`)
- Base noise per generation and layer: `E = randn(out,in)` from `gen(gen_seed, salt=0)` (row-chunked 2^26 elements), stored in `noise_dtype` (bf16). Member n: signs `(s_n ∈ ±1^in, r_n ∈ ±1^out)` from `gen(member_seed, salt=1)`; table rows `S[k]=s`, `R[k]=sign*sigma*r`. `dW_n = sigma * sign * E ∘ (r_n s_n^T)`; forward `y = Wx + r ∘ (E (s ∘ x))`. Antithetic partner = same seed, sign −1.
- `exact` (reference), `fused` (addcmul), `out_only` (output signs only; different family), `gemm_only`/`none` (diagnostics).
- `rank=k` → `lowrank`: `E = A B`, `A ~ N(0,1/k)` (out×k), `B ~ N(0,1)` (k×in): two thin GEMMs, isotropic covariance, noise memory ~0 (0.3 GB at 7B vs 13–15 GB dense).
- `core`/`core2` (needs rank): `dW_n = sigma * A diag(c_n) B`, one k-sign vector per member (`gen(seed,4)`); members share A's column space / B's row space per generation (different distribution).
- `extras`: `embed` (row lookup term inside the graph), `head` (term on sampled rows **outside the graph**; slots of the rows = last scheduled token per request, computed in `set_token_slots` pre-forward to keep CPU/GPU overlap; scoring path uses `logit_override` via `_install_head_scoring`), `norm` gains (per-slot relative table `out*(1+D[slot])`, `D = sigma*e/gain`), `bias` (per-slot table). Vectors get their own Gaussian per member (`gen(seed,3)`), fp32 masters on GPU. Tied embed/head handled as one matrix.

### 3.3 Noise/seeding
- tid = `B8(vLLM module name)` (no `.weight`), `#norm`/`#bias` suffix for vectors; mixF with salts 0 (base E), 1 (signs), 2 (stochastic rounding), 3 (vector noise), 4 (core signs); mask 63-bit. Dev gen.
- Coordinator protocol: `(gen_seed, [(member_seed, sign)], sigma)` → workers; back: one fitness per member. Comms 3.4 KB out / 1.6 KB back per generation (128 members, 2 workers); weights bit-identical across 2 workers after 3 updates without exchanging weights (only same-model GPUs tested).

### 3.4 Update path
- `update(seeds, weights, step)` with `step = alpha/N` (caller): direction `sum_n w_n eps_n = E ∘ (R^T diag(w) S)` — exact, computed as a rank-|seeds| outer product masked by E, row-chunked (2^26 elements; ~1.5 GB fp32 temporaries). Duplicate seeds are merged (antithetic pairs → `w = z+ − z−`).
- `master='cpu'`: fp32 centre in host memory (exact accumulation; 7B ~15–40 s/update, +26 GB RAM per worker). `master='sr'`: no copy, seeded stochastic rounding into bf16 (1.5–2.4 s/update). Choice open (design.md "?"); benches use `sr`, class default `cpu`.
- `state()/load_state()`: per-layer centre (fp32 master or bf16 weight) + vector masters. `materialize(slot)/member_weight` for parity tests (slot logprobs vs materialised weights cosine 0.995–0.999; update rel. error 5.5e-4).

### 3.5 Throughput tricks and measured numbers (plan.md / design.md, Qwen2.5-7B, A100-40GB, WebShop 16 tasks × 8 = 128 episodes)
- Dense exact Flipout: 2.0–2.1× shared-weight upper bound per M tokens (prefill 2.0×, decode 1.84×; noise eats KV: 3.1 GiB / 58k tokens left). Concatenating W and E into one GEMM does not help.
- Low-rank 64: 1.23–1.26× (full coverage), core: 1.20–1.27×; multi-LoRA slots (rank 8, 128 adapters): 2.9× (slower than dense Flipout). Low-rank vs dense gradient-estimate quality: no distinguishable difference (grad_quality bench).
- Continuous (stream) scheduling via `llm_engine.add_request/step` (`run_stream`): +18% dense, +14% low-rank vs synchronous waves.
- Prefix cache: off by default; exact per-slot salt hits <1% (verl-agent prompts rebuilt each step); cross-member sharing is approximate (16–18% hit, 7–8% time). Callers must salt by slot (and population version); cache reset at every population change/update.
- Multi-GPU: seed-only communication; weak scaling flat, strong scaling 2.04× dense / 1.50× rank-64 on 2 GPUs.
- Known limits: fitness not reproducible across batch compositions (bf16 batch-shape rounding; antithetic diff correlation 0.15–0.54); norm/bias perturbations mostly drowned in bf16.

### 3.6 Downstream users of the design
- specialists_team `tasks/agentflow/es_server.py` (HTTP OpenAI-compatible server + `/es/*`): continuous batching thread, member chosen via model name `"<served>@m<k>"`; routes `/es/population, /es/clear, /es/update, /es/save, /es/load, /es/score, /es/score_multi, /es/hidden, /es/crn, /es/reset_prefix_cache, /es/prefix_mode, /es/member, /es/population_block, /es/update_block, /es/anchor, /es/decay, /es/steer_*`; clean-prefix scoring (prompt tokens on slot 0, salt only from first response block); CRN per-request seed = hash(salt, prompt). Backends: `--perturb flipout|fura_s|iso` (+ optional `--steer-layers`). **`--vec-mode scalar` monkeypatches `fd._Vec.noise` at runtime** to one Gaussian per vector.
- TreeES `tree_es.py`, `update_probe.py`, `fix_merge.py` and specialists `es_countdown.py`, `agentflow/es_*.py` drive that server over HTTP.
- AgentES `train_flipout.py` uses `make_engine` in-process.

## 6. HarnessES `methods/steer_es/` (untracked repo)
- `steer_es.py` (numpy, float64, host-only): steering vectors per layer; noise **`np.random.default_rng([seed, layer]).standard_normal(d)`**, member offset `sigma * n_L * eps / sqrt(d)` with `n_L` = measured mean residual norm (fixed per layer; sigma relative to the residual norm on average, not per token). Antithetic slot order `[centre, +1, −1, +2, −2, ...]`.
- Update: `c_L += (alpha / pairs) * (z+ − z−) * n_L eps / sqrt(d)` with z over all 2P members, `alpha = kappa*sigma`, cosine sigma. **Divides by P, not 2P** (see R5). `History` json with config check + replay; centre npz per generation; pair seeds `default_rng([cfg.seed, g])`.
- Serving: `hes_steer/patch.py` patches vLLM 0.30 Gemma 4 inside `vllm serve`: per-layer table `T_L[slot]` added after the decoder layer via opaque custom op `hes::steer_add` (graph-safe; plain buffers were constant-folded by Inductor), slot from `vllm_xargs {"steer_slot": k}`, host-side slot buffer filled in `prepare_inputs`; prefix-cache salting via `steer_key` with **shared-system-prompt mode** (system-turn tokens unsteered → KV shared). `hes_steer/worker_ext.py` writes tables via `/collective_rpc hes_steer_load(npz)`; measure mode for `n_L`.

## 10. Numerics risks (same name, different numbers)

- **R1 FuraNative tid**: `B8(module_name)` (no `.weight`) vs `B8(module_name + ".weight")` in StructuredES / SeedReplayModelES / dense_inplace / rot_slots / IsoSeq / param_es_worker. Same seed → different fura_s noise. `test_fura_native.py` hides this by passing FuraNative's tids into StructuredES. Docstring "same draw StructuredES uses" holds only with injected tids. Affects any history replayed across `FuraSSlots` (TreeES/es_server) and `fura_s` scope servers.
- **R2 "fura_s" means four things**: absolute-sigma on closest-factor blocks of the fused vLLM weight (ESOpt, FuraNative, param_es_worker `fura_s`), relative `|S0| z` (param_es_worker `fura_s_rel`), paper layout relative with per-projection/per-head blocks and sequential keys (`fura_s_paper`; ES-SEAgent spec `"kind": "fura_s"` = this one), HF naming (`fura_s_pretransform`). sigma values are not portable (absolute 1e-3-ish vs relative 0.03).
- **R3 "full" / dense means three distributions**: i.i.d. Gaussian per member (seeded_model_es, vllm_math_es_worker, dense_inplace, specialists dense, param_es_worker full), Flipout sign-flips of one shared E per generation (DenseFlipout exact), low-rank AB Flipout / core (rank>0). Histories are not interchangeable; Flipout histories need `gen_seed`.
- **R4 chunking and RNG call pattern**: seeded_model_es / worker / specialists dense draw in 8M-element chunks; dense_inplace draws one `randn(p.shape)`; DenseFlipout draws row chunks of 2^26/in elements; FuraNative `noise_block(seed, n)[0]` is a single `randn((n, n_blk, b))` and is not `noise(seed)`. On CUDA Philox, different call patterns give different values for tensors larger than the chunk, so "same tid + same seed" is not sufficient for equality.
- **R5 update scale**: Agentic form alpha/N with N = number of members (ESOpt, MobileWorld `N=2P`, ES-SEAgent d7, TreeES `alpha/P` with P members) vs HarnessES `alpha/pairs` (2× larger step for the same alpha) vs train_flipout `alpha/E` (episodes, or alpha/M for `member` norm) vs ForkES/rot_tp classic `1/(2 sigma)` or `1/sigma^2·noise` gradient (+Adam) vs ES-SEAgent entropic `sigma * (q+ − q−)` vs TreeES `kappa*sigma/||w||`. The memory note "ES defaults = alpha/N, z in population" is implemented with at least three meanings of N.
- **R6 mask / mix**: mix64 (`seed ^ tid`, 64-bit) vs mixF (`(seed*1000003 + salt) ^ tid`, 63-bit) vs rot angle mix with golden-ratio constant vs LoRA init `(init_seed*1000003 ^ tid)` vs crc32 tid (LoraPop).
- **R7 CPU vs device generators**: steering (SteerSlots, SteerPopulation, SteerES) and RotSlots pairings use CPU generators; everything else uses device generators. Cross-GPU-type bitwise equality untested (design.md).
- **R8 storage precision**: StructuredES fura_s fp32 coef vs BatchedStructuredES bf16 core + stochastic rounding (stored update cosine 0.83–0.84 to exact after 10 steps) vs DenseFlipout `cpu` fp32 master vs `sr` vs dense_inplace bf16 backup + SR vs param_es_worker fp32 theta + exact render. Same scope name, different trajectories.
- **R9 runtime monkeypatches** that change numerics without code in the library: es_server `--vec-mode scalar` (`fd._Vec.noise`), train_flipout `_norm_forward` (Qwen3) and `--basis` (`set_noise`), IsoSeq `StructuredES._init_iso`, engine.py `vllm.LLM` and `GPUModelRunner.load_model` swaps.
- **R10 batched isobtt** uses a shared, sign-flipped generator → not the unbatched isobtt distribution (documented in README; runner checks option on resume).
- **R11 rot_tp** members differ from tp=1 members (pairs restricted to shards).
- **R12 steering scale**: per-token relative (`alpha*||x||`, SteerSlots/SteerPopulation, rot `add` uses rms(y)) vs fixed per-layer relative (HarnessES `n_L/sqrt(d)`, structes `RMS`) vs absolute (SteerES, param_es_worker `steer`). "sigma" for steering is not comparable across projects.
- **R13 slot routing keys**: `extra_args["slot"]` (SlotEngine), `["es_member"]` (vllm_math_es_worker, 0-based, −1 base), `["member"]` (specialists), `["es_slot"]` (structes), `vllm_xargs["steer_slot"]` (HarnessES), model name `@m<k>` (es_server). Slot 0 = base in some, = trained centre in others (`route_all`).
- **R14 reward normalisation details**: `centered_rank` in seeded_model_es = rank/(n−1) − 0.5 (ties broken arbitrarily by argsort) vs train_flipout rank with tie-averaging then std-normalised; std eps 1e-8 vs 1e-6 (AgentES); groups with zero std → zeros in some, eps-divided in others.
- **R15 prefix cache**: SlotEngine forces it off; engine.py re-enables it via `vllm.LLM` patch; es_server salts per (slot, pop_version) with clean-prefix mode; HarnessES salts per (table version, slot) with shared system prompt. A shared engine must own the salt policy or KV leaks across members.

## 12. Open decisions (for the user)

1. **Canonical noise spec**: tid source (vLLM fused module name vs HF name), `.weight` suffix, mix64 vs mixF (63-bit, salts), chunk size / single-call policy, device vs CPU generators. And whether legacy specs are kept so existing histories (MobileWorld, ES-SEAgent, HarnessES, AgentES LoRA) replay bit-exactly, or old runs are frozen.
2. **Canonical update form**: alpha/N with N = all members (antithetic counted twice) as in ESOpt/MobileWorld, or N = pairs (HarnessES)? Is step passed pre-divided (Flipout/es_server) or computed server-side from rewards (ESOpt `/es/update`)? Where normalisation lives (client vs server).
3. **sigma naming**: rename scopes so the convention is in the name (e.g. `fura_s_abs`, `fura_s_rel`, layout option `paper`), and decide the default layout for fura_s.
4. **Default perturbation family** (design.md "?"): dense exact Flipout vs low-rank-64 Flipout vs core; and default `extras` (embed/head/norm/bias; vec_mode scalar?).
5. **Centre precision**: fp32 CPU master vs stochastic rounding (design.md "?"); same question for FuRA-S batched cores (bf16+SR) vs fp32.
6. **Serving model**: in-process `SlotEngine` (current AgentES/AgentES-System/es_server) vs `vllm serve` + `collective_rpc` worker extension (MobileWorld, ES-SEAgent, HarnessES, rot_tp) — support both, or migrate one way; one slot key name; slot 0 = base or centre.
7. **vLLM version pin(s)**: SlotEngine patches private runner internals (`_model_forward`, `req_indices`, `query_start_loc`, `_get_prompt_logprobs_dict`); HarnessES targets vLLM 0.30 Gemma 4. One pinned version or per-backend compatibility shims.
8. **Steering**: which of the five steering designs is canonical (basis, scale, injection site, RNG), and whether HarnessES's numpy host-side ES stays separate (it runs in the pinned tau2 env).
9. **Where the library lives and who owns it**: new repo vs promoting `Agentic-ESOpt/algorithms/es`; first commit the untracked files (ESOpt `algorithms/es/*`, AgentES-System, ForkES, TreeES, HarnessES, specialists perturb + agentflow) so the migration has a base to diff against.
10. **Monkeypatches**: move Qwen3 norm fix, `--basis`, `vec_mode scalar`, `IsoSeq` CPU master into explicit backend options.
11. **Prefix-cache policy** owned by the engine (salt per slot+population version; clean-prefix and shared-system-prompt as explicit modes).
12. **Resume contract**: one history schema + backend `state()` checkpoint for every backend (required by the always-resumable and always-dump-rollouts rules); Flipout records must store `gen_seed` and signs.
13. **Sequential-member drivers** (ES-SEAgent moves the centre with `pes_update(±sigma)`): keep, or switch them to slot backends.
